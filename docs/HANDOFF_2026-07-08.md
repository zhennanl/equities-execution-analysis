## 0. Mission

**End goal:** an execution algorithm simulator (Page 1) and index-rebalancing
analysis (Page 2) that impress industry practitioners — functionality as
close to institutional tools as possible, with realistic limitations (data
feeds, venue access) *bypassed via clearly-labelled statistical simulation,
never faked*. The project is a job-application artifact for GSET/CLSA-type
quantitative execution roles; every design choice may be probed in an
interview, so honesty and auditability beat feature count.

**Mode:** continuous self-improvement. Each session: pick the next backlog
item (§4), implement with the protocols (§2), verify with the checklist (§5),
update the docs/registers, write a session summary. Do not ask the user for
permission — decide via the rules in §3.

## 2. OPERATING PROTOCOLS — encode real incidents; follow literally

**P-1. Never use the Edit tool on `app.py` or any file > ~300 lines.** The
Edit tool silently truncated `app.py` once and `agent12` once. Instead, patch
via bash-python: read file → `assert s.count(anchor) == 1` for EVERY anchor →
string replace → single `write_text` at the end. If any assert fails, nothing
is written (safe). After every patch: `wc -l`, `python3 -m py_compile`, and
inspect `tail`. If a file ever looks truncated, compare against
`git show HEAD:<file>` immediately.

**P-2. Stale bytecode trap.** The mounted filesystem produces same-second
mtimes, so Python reuses stale `.pyc` even after edits, and you CANNOT delete
`agents/__pycache__` (permission denied). Prefix every bash python run with
`export PYTHONPYCACHEPREFIX=/tmp/pycache`. If an edit "didn't take", this is
why.

**P-3. Verification gate.** A change is not done until: (a) `py_compile` on
all touched files passes; (b) a unit test with HAND-COMPUTABLE numbers passes
(e.g. "5% cap × 78 bars × 10k volume ⇒ 25% fill", "30bp up-wick ⇒ 10.0 bps
TWAP slippage"); (c) the AppTest smoke passes on BOTH pages. Never mark a
task complete with a failing check. AppTest recipe:
```python
export PYTHONPYCACHEPREFIX=/tmp/pycache
from streamlit.testing.v1 import AppTest
at = AppTest.from_file("app.py", default_timeout=40); at.run()
at.selectbox[0].set_value("US"); at.run()          # market BEFORE ticker
at.text_input[0].set_value("AAPL")
[b for b in at.button if "Run Agent Pipeline" in b.label][0].click().run()
assert not at.exception
at.sidebar.radio[0].set_value("🔄 Index Rebalancing Analysis").run()
```
Pipe stderr through `grep -v "use_container_width\|Arrow\|ScriptRunContext"` —
pyarrow serialization noise in AppTest is benign and pre-existing. Sandbox
needs: `pip install --break-system-packages yfinance streamlit plotly scipy
requests beautifulsoup4` and `pip install --user --upgrade jinja2 markupsafe`.
AppTest session_state does not support `.get()`; bash `timeout` max is 44s.

**P-4. Backward compatibility invariant.** A default `OrderTicket()` must
reproduce pre-ticket numbers EXACTLY (`is_default()` short-circuits the
constraint path). Add dataclass fields only at the END with defaults —
positional constructors exist. Test this invariant after touching Agents 3/4.

**P-5. Streamlit state rules.** `st.session_state.setdefault(key, ...)`
BEFORE widget creation; never pass `value=` to a widget that also has a key
you set programmatically. Buttons are True only on their click-rerun —
persist results to session_state (`p1_ctx`, `p2_es` patterns). Nested
expanders are illegal — use tabs inside expanders. When `market` changes,
`tk_start`/`tk_end` are reset via the `tk_market` sentinel — preserve that.
Interactive result sections must live OUTSIDE `if run:` blocks, reading
session_state.

**P-6. Numbers are quoted externally.** Changing σ estimators, fill
conventions, or η shifts every displayed number. That's fine when justified
by literature (document in `EXECUTION_SIMULATOR_RESEARCH.md`), but always
list "numbers will shift" in the session summary.

**P-7. Docs discipline.** After any feature: sync `docs/INSTITUTIONAL_GAP_REGISTER.md`
status (✅/◐ + date), `README.md` (user expects README updates), and the
relevant research doc. Never proactively edit `PROJECT_CONTEXT.md` or
`INTERVIEW_PREP.md`. Keep the user's concise-response preference.

**P-8. Network.** web_fetch works for MSCI/LSEG/PRNewswire/Yahoo; the sandbox
can run the app's own fetchers (verified). Yahoo rate-limits: keep fetch
tests to 1-2 per session, reuse `fetch_market_data("AAPL","US")`. Provider
pages are ToU-sensitive: never increase automated fetch frequency.

## 3. AUTOPILOT RULES

1. **Never wait for the user.** Choose using: backlog order (§4) → protocols
   (§2) → the honesty principle (label models, never fake data) → smallest
   reversible step.
2. **One backlog item at a time**, fully verified before the next.
3. **Timebox failures:** if the same failing approach resists 3 distinct
   fix attempts, revert the touched files (`git checkout -- <file>` if
   committed baseline exists; otherwise restore from your own pre-edit copy —
   ALWAYS `cp <file> /tmp/backup_<file>` before patching new-module files),
   write up the blocker in the session summary, move to the next item.
4. **Do not `git commit` or `git push`** — the user reviews and commits.
   Do not create/modify GitHub workflows beyond what exists without noting it
   prominently.
5. **Record everything:** end each session by writing
   `docs/SESSION_SUMMARY_<date>.md` — what changed, decisions made
   autonomously and why, numbers that shifted, blockers, next step. This is
   the continuity mechanism; assume the next session starts from this doc.
6. **Scope discipline:** do not redesign working subsystems; extend them.
   If a critique suggests a rewrite, log it in the register instead.
7. **When the user IS present** and gives a direction mid-session, their
   direction overrides the backlog order but not the protocols.
